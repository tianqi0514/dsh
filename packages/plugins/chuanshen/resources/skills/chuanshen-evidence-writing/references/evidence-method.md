# 证据、事实与专业论证

## 五层如何进入文章

Evidence 固定来源位置与版本；Entity 固定对象身份；Claim 保留“材料这样说”；Fact 是当前项目采用的已确认说法；Relation 是有事实和来源支撑的关系。正文是这些对象的可读投影，不是另一份独立权威数据库。

先为每章整理小型证据矩阵：本章要回答的问题 → 采用的 Fact / 计算 / 推演 → Evidence → 适用范围 → 未确定项。一个段落可以综合多项依据，但每个具体断言必须有对应支持，不以段尾堆引用掩盖没有证据的结论。

| 内容 | 写作方式 | 必要核验 |
| --- | --- | --- |
| 已确认事实 | 忠实陈述，保留时间、范围与单位 | verified、当前有效、本文适用；数字精确绑定 |
| 材料陈述 | 用“材料提出/记载”等归属语言 | Claim 的原文与来源；不伪装为客观已核验事实 |
| 计算结果 | 陈述结果，必要时解释口径 | 公式运行、输入版本、单位、舍入、缺值 |
| 规则结论 | 写明适用条件和建议性质 | Semantica 实际运行、前提、规则版本、证明链 |
| 制度和标准 | 引用真正支持当前表述的条款 | 发布方、版本、有效性、地区和使用范围 |
| 分析性叙述 | 组织论证、解释影响、提出有条件建议 | 不引入新的精确事实，不虚构职责、因果或行政批准 |

已绑定不等于已证明：同一页出现一个数字，不表示它支持当前指标；主体相同不表示统计周期相同；提及合作不表示隶属；满足一个必要条件不表示充分满足所有条件。原文不足时减少断言强度、改为待验证问题或补充来源，不能随意找一个可用 ID 填上。

## 借形不借值

历史语料使用 `chuanshen_corpus_create`、`chuanshen_corpus_manifest`、`chuanshen_corpus_artifacts` 获取真实版本和脱敏骨架。不要读取或转交带历史原值的段落作为本次事实，也不把 skeleton 占位符当数值。使用 `chuanshen_inheritance_preview` 和 `chuanshen_inheritance_todo` 查看可对齐、需换算、需重算、待补和不适用项；只有用户明确选择后才调用 `chuanshen_inheritance_apply`，禁止自动继承系数或过去的判定结论。

## 论证质量

每章围绕一个任务展开：说明现状和约束，解释资料之间的联系，比较可行选择，形成与证据强度相称的结论。可研报告应说明“为什么需要、规模为何合适、方案如何落实、成本和风险能否承受”；不能仅用投资数字堆成完整可研。

禁止虚构正式机构、文号、法规、责任划分或签发。需要公开标准时仅使用本次会话已授权且实际可用的联网/MCP能力；没有联网能力就列出待核验标准，不生成网址和摘录。外部来源先取得可固定版本的回执，并通过平台纳入项目，工作包未包含的 ID 不能直接提交正文绑定。

来源冲突应并列展示，不按“最新”或“多数”静默裁决。章节缺失项具体到内容和依据；空泛“加强组织领导”不能替代未知的负责单位。语言应像业务文章，避免“系统已完成”“以下是工具返回”等技术叙述。
