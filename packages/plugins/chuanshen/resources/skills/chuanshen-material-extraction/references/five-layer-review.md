# 五层抽取核验方法

五层不是五次必须执行的模型调用。解析服务产生 Evidence，抽取提出实体和陈述候选，程序归一与校验形成 Fact/Relation 候选，治理决定哪些版本可以采用。Agent 的任务是审读和提出可核验问题，不另造一套抽取数据库。

| 对象 | 要回答的问题 | 核验方式 |
| --- | --- | --- |
| Evidence | 依据实际在哪里？ | 原文件版本、片段原文与页码/行列能相互对应；不能由模型生成出处 |
| Entity | 说的是谁或什么对象？ | 标准名称、别名、主体标识、范围；重名不等于同一实体 |
| Claim | 哪份材料声称什么？ | 主体、谓词、值/客体、时间、条件都忠于原文；材料说法不直接升级为事实 |
| Fact | 本文采用哪个已确认说法？ | 核验状态、确认者、版本、有效时间与用途；拒绝、冲突、过期候选不进入正式数值 |
| Relation | 两个实体什么关系，靠什么证明？ | 关系型 Fact 对应的 Claim 和 Evidence；不要仅因共现添加因果或隶属关系 |

关系来源链必须能够回到 Relation → Fact → Claim → Evidence → 文档版本。ID 存在和引用链完整只是必要条件，还应逐项检查原文是否真正支持该关系和适用范围；“与某组织合作”不支持“隶属该组织”，“建议”不支持“已批准”。

数字须区分原子输入、文中转述的计算结果和正式 ComputationRun；不要把历史报告表格合计默认为当前项目正式计算。记录单位、含税口径、统计周期、对象范围及空值。空值不等于零；不同量纲不可直接比较或相加。

重点确认高影响口径：控制总额、关键单价、人员/资源基数、时间、约束阈值、正式机构职责。冲突项并列展示两个来源及差异，由用户选择采用范围或补证；不要以置信度最高、发布时间较新等单一条件静默覆盖人工决定。

样稿只提供结构和表达方法。即使其中名字、数字和结论看起来合理，也不能成为新项目的已核验事实。制度中的通用条件可以成为待确认的规则依据，但模型写出的规则草稿不等于 Semantica 已执行。
