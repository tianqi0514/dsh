# 材料用途与解析诊断

## 用途决定什么

| 用途 | material_role | 能用于写作什么 | 不能自动当作什么 |
| --- | --- | --- | --- |
| 本次业务资料、指标台账 | task_data | 本项目事实候选、原始输入及口径 | 已核验事实或权威计算结果 |
| 政策与制度 | policy_basis | 适用性核实后的约束、职责、标准 | 无条件适用于当前地区或时间的规定 |
| 参考材料 | reference | 对照、研究参考和背景线索 | 本次项目数值、结论和正式职责 |
| 样稿与格式 | sample_style | 目录、章节职责、表格、表达和排版 | 当前项目业务 Fact |
| 报告附件 | report_attachment | 附件结构；依内容确认后使用业务信息 | 默认已发布事实 |

台账使用 task_data；不要发明工具未支持的枚举。文件用途和“当前有效 / 历史 / 待核验 / 失效”是两种不同维度。一个混合文件含样稿与本次数据时，先明确各部分用途，不将全文作为本次事实发布。

## 解析策略

Markdown、CSV、JSON 等文本与结构化表格优先保留原生文字、行列和字段；普通文本不应为显示 OCR 能力而转图片识别。PDF 先区分文字页、扫描页和混合页，扫描区域才需要 OCR；表格保留工作表、行列或页内结构。具体策略由平台真实解析器执行，Agent 不能用提示词保证某解析器存在或已经执行。

OCR 输出是识别候选：名称、金额、单位、表头、跨页续表要比对原图。可用置信度低、单位缺失或图文不一致时标记问题；没有返回置信度就说“平台未提供”，不可编一个分数。失败先读加工记录和业务错误，再决定是否由用户修正材料或重试失败目标，不无限重传文件。

证据最少应定位到文件版本和真实片段；可用时附页码、工作表、表格行列、结构路径。没有页码的纯文本可以用结构路径，不伪造页码。引用必须保持所采用版本；上传新版本后检查发布版本是否纳入新材料，不能因列表出现文件就假定本章检索已更新。

## 完成判断

上传成功只表示平台收到文件；任务完成不一定四个目标全成功；候选生成不表示治理完成；图谱发布不表示所有事实都适用当前写作。分别记录真实状态。若当前 MCP 数据参与写作，保留提供方、查询时间、单位、适用范围及快照回执，不把会变的实时值冒充锁定文稿依据。
