## 验证边界

DSH 原生项目拥有 Workspace、Session、模型、连接器、Skill 和主笔组合；DSH 原生 Agent 读取章节工作包并提交正文。智库负责材料解析、已确认事实、确定性计算、规则结果、正文绑定、版本、质量闸门和导出。Plate 作为独立右侧资源编辑器，不接管 Office。

本记录只陈述本轮实际执行结果。单元/契约测试、真实模型与浏览器闭环、尚未验证范围分开列示，避免以代码存在或接口返回替代业务验收。

### 事实变更、影响预览和回滚

以土建综合单价为权威输入，实际执行 `2500 → 2700`：

- 确定性重算得到土建工程费 `45,797,500 → 49,461,300` 元；建安工程费 `111,880,030 → 115,543,830` 元；已知费用小计 `130,320,030 → 133,983,830` 元；差额 `30 → 3,663,830` 元；建安工程费占比 `85.8502% → 86.2371%`。
- 影响预览返回 6 项确定影响和 1 项需人工复核的语义影响。应用前正文、正式事实和历史版本均未改变。
- 第一次预览执行取消，正文保持不变。第二次预览取消选择结论项，只应用 5/6 项确定影响。
- 选择性应用生成 v13；两个未采用位置保留旧投影并标记 stale，发布质量闸门真实拒绝该版本。
- 回滚不改写历史版本，而是形成新的 v14；权威值、计算投影和正文恢复一致，发布校验重新通过。
- 这条链路使用稳定绑定、确定性依赖和不可变版本；没有对数值执行全文字符串替换，也没有重写整篇报告。

### 浏览器问题与修复

导出任务后端状态为 `succeeded`，Plate 原界面只在状态为 `completed` 时显示下载按钮，造成“任务成功但无法下载”。已将前端就绪判断改为接受正式状态 `succeeded`，同时兼容旧状态 `completed`，并校验下载任务标识。构建、类型检查、单元测试和部署已经完成。部署后浏览器真实显示两个下载按钮；点击 PDF 和 DOCX 后，下载代理均返回 HTTP 200、正确 MIME 类型和附件文件名。浏览器下载事件本身受验收容器接管，但服务端对象、摘要、响应头和逐页渲染已经形成完整证据链。

## 测试中发现并修复

1. 运行服务使用的 Profile 与最初安装候选的位置不一致；已按实际运行目录部署并以浏览器加载结果核验，不能再用“安装命令成功”代替运行验证。
2. 安装过程曾改变 Profile 清单的文件归属，导致服务账号无法读取；已恢复归属并保留包管理存储边界说明。
3. Projects 的状态 Hook 曾位于组件外，生产包导入失败；已移入组件，并增加真实 React factory 导入测试。
4. 官方只读 Skill 能被发现但原管理层不能形成固定修订；已从官方资源入口读取不可变快照，同时校验越界、符号链接、深度和大小。
5. 长公式链能重算但传播证明曾受默认深度限制；现已补传播上限与超限回归。
6. Plate 下载按钮把后端 `succeeded` 状态误写成 `completed`；已修复并覆盖两种兼容状态及非法任务标识反例。

### 当前限制

- 当前是受限内网单用户候选，不是完整多租户委托授权验收。
- 连接器与 Skill 的“已配置”不等于每轮均被模型实际调用；真实调用仍以 Session 工具事件为准。
- 正文绑定与数字校验不能自动证明全部分析性叙述在业务上正确，正式交付仍需人工审读。
- Plate 已验证本次编辑、变更、版本和导出主线；不据此宣称完整协同、所有高级插件和所有 Office 互操作均已验收。
- DOCX 的跨页表格目前可读，但尚未实现或验收每页自动重复表头；正式客户模板、封面和目录需按实际交付模板继续配置。
- 浏览器容器未暴露本机“下载完成”事件，因此验收以真实按钮点击、代理 200 响应、正确附件响应头、对象摘要一致和导出文件逐页渲染共同签收；没有用静态副本替代导出任务。
- 本轮没有把缺失值强制补零；依赖未定义输入的完整总投资继续保持不可评估。
