# DSH 原生推演写作设计复核

日期：2026-09-20。性质：源码与锁定版本契约审核、实施设计及本轮候选验收总结。生产边界以文末“真实验证与限制”为准。

## 1. 结论与审核范围

继续采用 DSH 原生项目、Session、MCP 连接器、Skill、专家及官方 Agent Teams；传神智库作为解析、知识、计算、规则、文稿版本和校验服务；Plate 作为独立编辑插件；现有 Office 不改归属、不接管。

方向已经按“选择能力 → 实际执行 → 文稿绑定 → 用户接受”完成一条科研楼可研候选闭环。实现没有增加平行的传神项目工作台、聊天框、技能注册表或 Agent 调度器；仍需将正式模板、多用户授权及生产外部数据源留给后续验收。

本轮审核基线：

- DSH：`codex/controlled-writing-plugin`；本轮从已确认基线增量实现。
- 智库：`codex/controlled-writing-bidirectional-diff`；已有无关修改未被覆盖。
- 官方公开契约：本仓库 `docs/dsh-v0.1.6-alpha.2/`；没有据此推定服务器安装状态。
- 实际候选重新通过模型、API、数据库、对象存储、浏览器及渲染产物核验；不以官方文档或本地测试推定服务器状态。

## 2. 优先修改的设计

### P0-1：项目选择必须形成可核验的运行组合

当前 `packages/plugins/projects/src/runtime/context-injection.ts` 注入技能名称与修订；`docs/PROJECT-DESIGN.md` 明确区分项目推荐与原生 `skill({name})` 实际加载。`projects/src/client.tsx` 的 startTask 创建普通 Session、关联材料和连接器，但没有调用现有专家执行创建链。

调整：

- 项目保存可用专家、推荐技能、数据连接、资料；启动任务时选择一位主笔，缺省可以使用普通 Agent。
- 有专家时复用专家公开执行服务及其不可变 preset/Skill 修订，不能从其他插件导入内部管理器。
- 明确区分“项目已配置”“本次已挂载”“本次实际调用”；实际调用以原生 Session 工具事件为证据。
- 按官方能力装配或让用户经原生 `/` 调用技能，不发明当前版本没有的强制激活接口。未加载技能时不能显示“已使用该方法”。
- 项目关联经校验的 Workspace，不能跟随当前浏览会话或任取第一个目录。Workspace 仍不是权限边界。

### P0-2：本链路的写作 Agent 由 DSH 拥有

当前 `chuanshen/src/tools.ts` 的 `chuanshen_writing_generation_step` 调用智库 `/generation-runs/{id}/agent`；智库 `apps/api/writing.py` 再创建 WritingAgentSession 并执行 `_stream_turn`。因此 DSH 专家目前可能只是一个外层调用者，不能认定文章由项目选择的专家、技能和模型生成。

调整为：

1. 智库准备章节工作包：任务、目录、已确认事实、证据、确定性计算及规则结果、缺失项。
2. 当前 DSH 主笔或官方 Team 子专家读取工作包，实际组织章节与语言。
3. 提交结构化章节结果和绑定建议。
4. 智库执行 Schema、来源、数字、适用范围、版本及质量校验，通过后形成正文版本；失败返回可修复问题。

DSH 负责 Agent 执行、模型、取消、工具事件；智库继续负责持久业务任务与确定性处理，不另建 Agent 循环。平台原有妙笔入口可以保留原执行适配，但 DSH 写作路径不应同时启动内外两套 Agent。重试只针对失败章节，任务创建不等于成稿。

### P0-3：Plate 独立交互，正文不复制一套权威存储

官方 Deliverables 是文件交付，不是任意文稿对象注册表。Plate 应使用官方 Client Resource、`ctx.sidebarRightTabs`、keyed `sidebar.right.pane.tab` 和 `ctx.sidebarRight.openResource`，注册独立资源协议及 tab kind，不接管 Office 或 `.docx` 默认入口。

- 智库写作服务已有 WritingDocumentVersion、WritingChunk 和绑定，继续作为本阶段正文与依据的权威来源。
- DSH 保存项目、Session 与该文稿的关联；Plate 保存可恢复的临时编辑状态，不维护第二份“当前正式正文”。
- 普通段落、表格和简洁引用留在正文；依据、公式、推演和影响按选区在辅助区展开。
- 右侧用原生停靠面打开 Plate，复用其展开、分栏、浮出能力；不嵌套第二套全局导航。
- DOCX/PDF 是指定文稿版本的导出快照，再经原生文件交付。Office 可以处理该文件，但它的编辑不会被假定自动反写 Plate 绑定。

### P0-4：绑定要精确到每次出现的位置

智库 `packages/platform/writing_impact.py` 目前先定位已绑定块，再寻找旧数字的唯一出现位置；重复出现会拒绝自动修改。这不是全篇替换，但还不够支撑复杂摘要、表格与正文重复引用。

补充稳定 `block_id + occurrence_id`，表格位置有稳定 `cell_id`；每个受控内容位置关联 FactVersion 或 ComputationRun，并记录单位、显示单位、舍入及格式。块级绑定用来解释段落，位置级绑定用来准确更新值，两者保留。

- 相同数字但不同指标不能混淆。
- 同一指标重复出现，每个位置都能找到。
- 元与万元是显示变换，不产生另一套权威值。
- 剪切、拆段、合段、粘贴、表格合并和删除必须维护或明确失效绑定。
- 修改普通措辞默认只改本处；修改受控值进入候选事实变更，不自动确认新事实。
- 没有绑定的相似文字只能作为疑似影响，不能承诺全覆盖。

### P0-5：用户确认、选择性应用与并发需要真实契约

`chuanshen_writing_change_apply` 当前检查模型参数 `user_confirmed`。该布尔值本身不是用户操作证明；本轮未验证其他审批策略是否补足此处，不能仅据它宣称强制用户确认。

调整：

- Agent 可以提出候选、请求预览；提交必须取得受信 UI 选择回执，或可核验的原生审批结果与业务确认记录。
- 回执绑定用户、preview、候选值、被选项目和基线摘要；模型不能自签。
- 预览覆盖所有实际读取的输入事实、规则、公式、计算、依赖图及正文版本；其中任一变化，重新预览。
- 普通文稿保存也需要 `base_version_id` 和操作幂等标识。现有 WritingDocumentVersionCreate 未携带预期版本，不足以防止双开覆盖。
- 选择性应用更新权威事实及所选正文投影；未选处保留旧值、旧绑定并标记 stale。界面显示“事实已更新，仍有 N 处正文待更新”。
- 有 stale 或不支持的事实陈述时可保存草稿，但不能通过正式定稿。允许逐项采用不等于允许不一致的正式报告。
- 历史版本不变，回滚形成新版本；已有后续变更时检测冲突，不能粗暴恢复旧快照。

### P1-1：MCP 接入、附件与专家共享要统一到真实项目范围

当前连接器按主 Session 记录选择，并按 `mcp__server__` 工具名前缀限制工具。未见这一选择自动传播到 Team 子成员；资源和服务指令也需要验证，不能把工具过滤当完整隔离。本轮是源码风险判断，不是已复现越权。

- 复用官方 MCP 客户端与 scope，主笔及每个子专家都重新解析允许的连接、资源和资料。
- MCP 返回值落为带来源、时间、单位、范围和校验状态的快照；写作引用固定快照，不在生成到一半无提示换用新值。
- 附件从原生不可变上传回执转交解析服务，校验归属与内容摘要；用户不需要手工复制到插件允许的本地目录。
- 原文件归资产 owner，智库解析是其派生产物，记录关联；确需跨系统复制时可追踪，不维护两个无关联的当前文件。
- 缺少真实业务数据源时，可用按固定测试输入执行真实查询的隔离 MCP 服务验证协议，但不得标注成客户生产系统接入成功。

### P1-2：Skill 沉淀写作方法，专家承担交付职责

首轮只需三组可复用方法，细节按需读取：

1. 证据约束写作：Entity/Claim/Fact/Evidence/Relation 的使用，冲突处理、适用范围、借形不借值、引用支持度。
2. 指标与推演：量纲、口径、缺值、公式依赖、何时使用 Semantica、如何解释结果。
3. 专业报告：目录职责、论证组织、正文与附表一致性、局部修订及交付检查。

方法写入官方格式 Skill 与 references，不继续把大段全局写作流程硬编码在 TypeScript 系统提示词。确定性计算、授权、定稿、版本提交仍由服务执行，不依靠 Skill 兜底。

首个场景使用一位可研主笔完成全文，需要时再请投资专家写投资章节；专家不是只能检查。子专家交付章节建议与依据，由主笔汇总并按版本提交。多专家按官方 Team 运行，不同时无条件覆盖整篇正文，成果归属不能仅假设由父子 Session 自动继承。

### P1-3：以一条业务流程组织界面与工具

保留“项目 → 原生对话 → Plate 文稿”的主入口。传神能力管理页可保留为诊断或高级入口，但不作为每次写作的必经工作台。

常用操作是：添加资料、核对关键输入、开始写作、查看依据、预览变更、应用所选、导出。无需普通用户逐个调用几十个工具或配置底层 ID。工具通过已有公开机制按当前任务组织，不另造工具注册表。

不能用输入只含金额的材料硬写完整可研报告。建设必要性、规模、实施条件、风险和依据应有足够材料；缺失章节明确待补，不能由空泛文字掩盖。

## 4. 必须执行的真实写作场景

场景：科研楼建设项目可行性研究报告讨论稿。采用真实业务写作流程和用户已有材料组织方式；构造项目值明确作为测试数据，不冒充已立项项目、正式造价结论或客户真实经营事实。

本轮使用六份独立科研楼测试材料（均按测试数据管理，不写入客户敏感信息）：

1. `01_项目建设基础资料.docx`
2. `02_建设规模与功能需求.docx`
3. `03_建设方案与实施条件.docx`
4. `04_投资估算与资金筹措.xlsx`
5. `05_可行性研究编制依据清单.md`
6. `06_关键口径核实清单.docx`

原业务 HTML 仅用于理解业务结构，不把静态展示当模型产物。材料中的业务值按本次测试事实治理，外部标准仍需检查发布机构、版本和有效性；依据清单不能冒充标准正文。

另有最小算术回归输入，它与六份完整材料是不同测试基线，不能混用数值。正式 Ground Truth 从本次实际上传材料计算，不把旧脚本中的数值硬灌进报告。

### 测试顺序与通过条件

| 环节 | 真实操作 | 必须保留的结果 |
| --- | --- | --- |
| 1 | 新建隔离 DSH 项目，选择主笔、Skill、连接和模型 | 项目/Session/Workspace 与实际执行组合 |
| 2 | 从浏览器上传六份材料，另选样稿时标明用途 | 不可变附件、智库解析任务、文件版本、页码/表格来源 |
| 3 | 提出关键事实与口径，用户确认冲突/缺项 | Claim→Evidence；确认者、FactVersion；样稿不变成本次事实 |
| 4 | 通过所选 MCP 查询一项当前数据 | 查询与来源回执、快照、单位、时间、使用范围 |
| 5 | 主笔拟目录，用户调整后逐章写作 | 实际 Skill 加载、专家身份、模型与工具事件 |
| 6 | 生成完整业务讨论稿而非数个展示段落 | 概况、依据、必要性、规模方案、实施、投资、风险、结论、附表；缺项明确 |
| 7 | Plate 打开并编辑、/ 指令、查段落依据 | 正文可用，引用能打开，关键数字/结论有真实绑定 |
| 8 | 修改土建单价，尚不应用 | 土建费→建安费→预备费→总投资→占比的路径与摘要、正文、表格影响；原文不变 |
| 9 | 取消，再全选应用，再回滚 | 取消不写正文，数值一致，历史不变、回滚新版本 |
| 10 | 再次预览并只选部分采用 | 未选处旧值/旧绑定且 stale；定稿阻断；不存在无关数字替换 |
| 11 | 重复值、万元显示、删缺利息、并发修改 | 按位置绑定；缺值不是零；过期预览/保存冲突被拒绝 |
| 12 | 同项目另一篇摘要稿、刷新及服务重启 | 跨文稿只提示不偷改；会话、文稿和绑定恢复 |
| 13 | 导出 Word/PDF 并实际打开 | 指定版本一致，中文、标题、表格、分页、依据和待补项正确 |

如果本场景没有经业务确认的关系判定规则，就不强行加入地震规则或把公式说成 Semantica 推演。按材料确认适用条件后再测相应真实规则；计算写作闭环与 Semantica 专项结果分开报告。

### 文章质量验收

逐章核对是否真正支持可研讨论：建设必要性是否有材料支持，建设规模与需求是否对应，投资章节是否可复核，风险是否具体，结论是否超出证据，是否虚构政策/机构/批复，是否存在空泛重复和拼接感。依据不仅要 ID 存在，还要原文确实支持所写内容。

先完成一位主笔的完整报告，再增加一次投资专家参与的章节写作，证明专家能够写作且返回同一文稿流程，不以多专家数量作为目标。保留会话、原文、计算结果、绑定、变更前后、导出文件及逐章差距记录。

## 5. 旧证据与新验收的区别

平台 `scripts/controlled_writing/verify_live.py` 的 research_flow 直接创建 Fact 和预设 Plate 节点，可用于计算/版本/联动接口回归，但不能证明“真实上传 → DSH 选中方法和专家 → 完整新文章 → 独立 Plate”的链路。

旧记录中的工具数量、一次单章节生成、历史 passed 和图谱数量不作为本次新链路的完成证据。新链路需从浏览器重新执行并核实产物；不能通过只展示旧对话宣称此次修改已验收。

## 6. 实施结果

本轮已按上述顺序完成候选实现和一次完整科研楼可研闭环：

1. DSH 项目保存并恢复 Workspace、连接器、固定 Skill 修订和本次主笔，原生 Agent 使用 `deepseek-v4-flash-0731` 执行章节写作。
2. 智库提供章节工作包、事实、来源和确定性计算；DSH 提交结构化章节，智库校验后形成不可变文稿版本。没有再启动第二套内层 Agent。
3. 新报告完成 10 个章节；当前回滚后的 v14 保存 43 项已确认事实、25 次确定性计算和 37 条正文绑定，发布校验无 stale、待确认或阻断问题。
4. 土建单价 `2500 → 2700` 形成 6 项确定影响和 1 项人工复核影响。取消不写正文；选择性应用后 v13 留下 2 个 stale，正式质量门拒绝；回滚形成新 v14 并恢复一致，没有改写历史。
5. Plate 实际打开 v14 并提供正文、依据、指标、版本和导出视图。导出状态兼容问题经浏览器发现并修复：后端成功状态为 `succeeded`，前端曾只识别 `completed`。
6. v14 的 DOCX/PDF 均真实导出、摘要核对、实际渲染为 3 页；包含 2 个表格，回滚前的 v13 数值未泄漏到导出文件。
7. 自动化回归分别通过：平台原生写作 76/76、平台公式/API 86/86、DSH 传神插件 26/26、连接器策略与超时 8/8、DSH Projects 19/19、Skill 固定修订 3/3、Plate 18/18。

## 7. 真实验证与限制

### 已真实验证

- 项目、真实模型、10 章新报告、正文绑定、质量闸门、影响预览、取消、部分应用、stale 阻断、回滚和历史版本。
